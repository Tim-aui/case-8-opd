# UX и Vision веб-части — Кейс № 8

**Версия:** 1.1  
**Дата:** 31.10.2026  
**Статус:** синхронизировано с утверждённой архитектурой сайта.

## 1. Назначение продукта

Сайт — рабочее место сотрудников библиотеки для поиска книг и читателей, оформления выдачи и возврата, контроля просрочек и просмотра KPI.

Пользователи сайта:

- библиотекарь;
- администратор.

Читатель приходит в библиотеку, выбирает книгу и обращается к библиотекарю. Самостоятельного интерфейса, регистрации и личного кабинета читателя в MVP нет.

## 2. Различие ролей

- Библиотекарь работает с каталогом, читателями, выдачами, возвратами и отчётом о просрочках; экспортирует отчёт CSV.
- Администратор импортирует CSV, формирует и экспортирует отчёт и дополнительно видит журнал изменений.
- В прототипе роль выбирается переключателем в шапке; настоящая авторизация не реализуется.

## 3. Измеримые UX-метрики

### UX-M-01. Оформление выдачи

Оформление выдачи из открытой карточки читателя — не более трёх основных действий:

1. Нажать «Выдать книгу».
2. Найти или выбрать свободный экземпляр.
3. Подтвердить выдачу.

Успех: выдача появилась в карточке читателя, а экземпляр стал недоступен для повторной активной выдачи.

### UX-M-02. Оформление возврата

Возврат из списка активных выдач — не более двух основных действий:

1. Выбрать активную выдачу.
2. Подтвердить возврат с указанной датой.

Успех: выдача перенесена в историю, экземпляр снова доступен, статус просрочки пересчитан.

### UX-M-03. Поиск просрочки

Карточка должника открывается из списка просрочек одним действием — нажатием на строку.

## 4. Экраны MVP

| Экран | Назначение | Доступ |
|---|---|---|
| Каталог | Поиск книг и экземпляров, отображение доступности | Библиотекарь, администратор |
| Карточка читателя | Текущие выдачи, история и просрочки читателя | Библиотекарь, администратор |
| Выдача / возврат | Оформление выдачи и приём книги | Библиотекарь, администратор |
| Просрочки | Список на выбранную дату, фильтры, переход к читателю | Библиотекарь, администратор |
| KPI-дашборд | Доля просрочек, среднее, медиана, ТОП-N читателей и книг | Библиотекарь, администратор |
| Журнал изменений | Кто, когда и что изменил по выдачам и возвратам | Только администратор |

Действия, включённые в MVP:

- «Импортировать CSV» — панель или модальное окно администратора;
- «Экспортировать CSV» — действие на экране «Просрочки», доступное библиотекарю и администратору.

## 5. Общая навигация

В шапке находятся:

- переключатель роли «Библиотекарь / Администратор»;
- дата отчёта;
- вкладки доступных экранов;
- индикатор состояния соединения с мок-сервером.

При выборе роли библиотекаря вкладка журнала скрыта. Остальные экраны и данные остаются доступными обеим ролям.

## 6. Ключевые сценарии

### Основной путь библиотекаря

```text
Каталог или Карточка читателя
-> Выдача / возврат
-> успешная операция
-> обновление списков
```

### Поиск должника

```text
Просрочки
-> Карточка читателя
-> Выдача / возврат
```

### Контроль администратора

```text
Журнал изменений
-> фильтрация по операции или дате
-> просмотр автора, времени и результата изменения
```

## 7. Состояния интерфейса

Каждый экран должен иметь состояния:

- загрузка;
- данные получены;
- пустой результат;
- ошибка валидации;
- серверная ошибка;
- отсутствие сети или таймаут;
- повторная загрузка.

Введённые пользователем данные не должны исчезать после серверной ошибки или потери соединения.

## 8. За границами MVP

- интерфейс читателя;
- бронирование;
- продление через личный кабинет;
- штрафы;
- email- и Telegram-уведомления;
- BI-интеграция;
- настоящая авторизация;
- управление пользователями и ролями;
- прямая интеграция сайта с 1С.

## 9. Критерии готовности UX

- все шесть экранов доступны в соответствии с ролью;
- журнал скрыт для библиотекаря и доступен администратору;
- основной сценарий выдачи проходит без ручного обновления страницы;
- возврат сразу обновляет доступность экземпляра;
- строка просрочки открывает карточку читателя;
- администратор может импортировать CSV и получить протокол проверки;
- библиотекарь и администратор могут экспортировать текущий отчёт CSV;
- ошибки мока отображаются понятным сообщением;
- при перезапуске мока демонстрационные данные восстанавливаются.
