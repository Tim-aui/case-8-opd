# Инсайты и требования — Кейс № 8

**Версия:** 1.1  
**Дата:** 31.10.2026  
**Основа:** реестр требований команды, решения D-7 и D-8, архитектура веб-части v0.3.

## Закреплённый реестр требований

| № | Инсайт | Потребность | Требование | Проверяемый критерий |
|---|---|---|---|---|
| R-08-1 | Исходные данные о книгах, читателях и выдачах поступают из нескольких CSV; ручной повторный ввод создаёт дубли и ошибки ссылок | Администратору нужна воспроизводимая загрузка данных | Система должна импортировать CSV `books`, `readers`, `loans`, проверять обязательные поля, ссылочную целостность и даты; повторный импорт выполняется идемпотентно по `loan_id` согласно D-7 | Корректный набор загружен; строки с неизвестными `reader_id` или `book_code` отклонены с причиной; повторная загрузка того же набора создаёт 0 дублей по `loan_id` |
| R-08-2 | Просрочки полезны только при одинаковом расчёте на выбранную дату | Сотруднику нужен воспроизводимый отчёт, совпадающий с эталоном | Система должна формировать отчёт о просрочках на дату D и считать календарные дни по единому правилу | Отчёт на T1 строится не более чем за 2 секунды; результат совпадает с `golden/overdue.csv`, расхождений 0 |
| R-08-3 | Результат отчёта необходимо передавать и проверять вне системы | Библиотекарю и администратору нужна выгрузка отчёта | Система должна экспортировать сформированный отчёт о просрочках в CSV | Обе роли получают CSV с теми же строками, датой отчёта и значениями, что показаны на экране; файл открывается без ручного исправления структуры |
| R-08-4 | Главная ежедневная операция — выдача конкретного экземпляра; повторная выдача занятой книги недопустима | Библиотекарю нужно быстро и безошибочно оформить выдачу | Система должна оформлять выдачу по `reader_id` и `book_code`, запрещать более одной активной выдачи экземпляра и проверять `issue_date <= due_date` | Свободная книга выдана не более чем за 3 основных действия; занятый экземпляр отклонён; некорректные даты не сохраняются; в журнал записаны автор и время операции |
| R-08-5 | Изменения состояния выдач должны быть прослеживаемыми | Администратору нужно видеть автора, время и результат операции | Система должна вести журнал выдач и возвратов, доступный только администратору | У библиотекаря вкладка отсутствует; администратор видит тип операции, `loan_id`, автора, дату-время и результат |

## Решения, применённые в критериях

- **D-7 — повторный импорт:** ключ идемпотентности выдачи — `loan_id`; повторная загрузка той же записи не создаёт дубль. Совпадающая запись пропускается, конфликтующая запись с тем же `loan_id` отклоняется и попадает в протокол.
- **D-8 — поля и даты:** экземпляр идентифицируется полем `book_code`; обязательны проверки `issue_date <= due_date` и, если возврат заполнен, `issue_date <= return_date`. Проверка `due_date <= return_date` запрещена: возврат до срока является корректным.

## Приоритет MVP

- **Обязательно:** R-08-1, R-08-2, R-08-3, R-08-4.
- **Обязательно для разграничения ролей:** R-08-5.
- **Не входит:** кабинет читателя, бронирование, штрафы, реальные уведомления, BI-интеграция и прямая связь веб-прототипа с 1С.
