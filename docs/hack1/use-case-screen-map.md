# Связь Use Case → экран — Кейс № 8

**Версия:** 1.2  
**Основа:** пять Use Case из официального чек-листа Хакатона 1.

## Матрица

| UC | Актор | Экран или элемент интерфейса | Ключевые шаги и результат |
|---|---|---|---|
| UC-08-1 Выдать книгу | Библиотекарь | Карточка читателя → Выдача / возврат | Выбрать читателя и свободный экземпляр, указать срок, подтвердить; создаётся активная выдача |
| UC-08-2 Принять возврат | Библиотекарь | Выдача / возврат | Найти активную выдачу, указать дату возврата, подтвердить; экземпляр освобождается |
| UC-08-3 Импортировать данные | Администратор | Панель администратора / модальное окно импорта | Выбрать CSV книг, читателей и выдач, запустить проверку, получить протокол; корректные записи загружаются без дублей |
| UC-08-4 Сформировать отчёт о просрочках | Библиотекарь, администратор | Просрочки + KPI | Выбрать дату и фильтры, сформировать строки и показатели отчёта |
| UC-08-5 Экспортировать CSV | Библиотекарь, администратор | Просрочки → «Экспорт CSV» | Сформировать отчёт и выгрузить его в согласованном формате |

Импорт можно реализовать модальным окном или вкладкой администратора, поэтому он не требует отдельного постоянного экрана. Экспорт является действием на экране «Просрочки» и доступен обеим рабочим ролям.

## Тексты для сценария «Выдать книгу»

| Ситуация | Текст сообщения | Поведение |
|---|---|---|
| Успешная выдача | «Книга выдана до ДД.ММ.ГГГГ» | Закрыть форму и обновить данные |
| Экземпляр уже выдан | «Экземпляр уже выдан другому читателю. Выберите доступный экземпляр» | Не создавать выдачу; сохранить читателя и даты |
| Читатель не найден | «Читатель не найден. Выберите существующего читателя» | Не создавать выдачу; подсветить поле читателя |
| Экземпляр не найден | «Экземпляр книги не найден в каталоге» | Не создавать выдачу; подсветить поле экземпляра |
| Неверные даты | «Дата планового возврата не может быть раньше даты выдачи» | Не создавать выдачу; подсветить срок возврата |
| Ошибка сохранения | «Не удалось оформить выдачу. Проверьте данные и повторите попытку» | Сохранить введённые данные и показать повтор действия |

## Перспективные взаимодействия

- BI-система в будущем может получать метрики сформированного отчёта.
- Сервис уведомлений в будущем может получать сведения о просрочках.
- Читатель не является актором MVP; интерфейс читателя имеет статус Could после MVP.
