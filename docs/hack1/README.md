## 3. Решения команды (зафиксированы тимлидом 31.10.2026)

| № | Вопрос | Решение | Источник / обоснование |
|---|---|---|---|
| D-1 | Имена полей | Как в карточке кейса: `books (book_code, title, author, year, udk)`, `readers (reader_id, fio, group)`, `loans (loan_id, reader_id, book_code, issue_date, due_date, return_date)` | «Кейсы ОПД», кейс 8, раздел «Данные». Совпадает с полями отчёта «Просрочки» (`reader_id, fio, book_code, title, days_overdue`). В наборе C8 те же поля называются `book_id / checkout / due / return`. Аналитик закрепляет маппинг в словаре данных к концу W2 |
| D-2 | Правило дат | `issue_date ≤ due_date` и, если `return_date` заполнена, `issue_date ≤ return_date`. Досрочный возврат допустим. Возврат после `due_date` допустим и считается просрочкой | В кейсе 8 есть два правила, и они противоречат друг другу: «если return_date задана — due_date ≤ return_date» (буквально запрещает досрочный возврат) и в наборе C8 «due ≥ checkout; если return, то return ≥ checkout». Берём правило C8. ☐ Согласовать с куратором |
| D-3 | Определение просрочки | Выдача просрочена, если `return_date` пуста и дата отчёта `D > due_date` (статус «Просрочена»), либо `return_date > due_date` (статус «Возвращена с просрочкой»). Дни календарные | Кейс 8, «Жизненный цикл выдачи» |
| D-4 | Статусы выдачи | «Выдана» → «Возвращена» (в срок) / «Просрочена» → «Возвращена с просрочкой». Статус не хранится, а вычисляется на дату (A-08-2) | Общее ТЗ, аналитик W3: «Выдана → Возвращена / Просрочена → Возвращена с просрочкой» |
| D-5 | Читатель | Роль Could. В хакатоне 1 у читателя нет Use Case, роль 1С для него не создаём, на C4 Context его не показываем | Кейс 8: «читатель (опционально, только просмотр своих выдач)». MoSCoW: Could |
| D-6 | Источник истины | 1С — единственная система учёта. Веб-прототип работает на мок-REST и не пишет в 1С | A-08-4 в [nfr.md](nfr.md) |
| D-7 | Повторный импорт выдачи с тем же `loan_id` | 1) Все поля совпадают → пропуск («дубль»). 2) В CSV появилась `return_date`, в 1С выдача активна → оформляется возврат («обновлено»). 3) В 1С возврат уже есть, в CSV `return_date` пуста → пропуск, 1С не затирается. 4) Любое другое расхождение (`reader_id`, `book_code`, `issue_date`, `due_date`, другая `return_date`) → строка отклоняется («конфликт с данными базы»), исправляет администратор вручную. Повторный импорт того же файла: создано = 0, обновлено = 0 | A-08-1, NFR-5, D-6 (1С — источник истины). ☐ Подтвердить реализуемость у 1С-разработчика |

## 4. Реестр номеров

Номера сквозные во всех файлах хакатона 1. Новый номер выдаёт тимлид, чтобы не было пересечений.

**Требования R-08-x.** Аналитик выводит их в `requirements.md` по цепочке «инсайт → потребность → требование → критерий». Номера и смысл ниже закреплены, формулировку и критерий даёт аналитик.

| № | Требование (кратко) | Из какого инсайта | Критерий (черновой) |
|---|---|---|---|
| R-08-1 | Загрузка books / readers / loans из CSV; повторная загрузка не создаёт дублей | И-1С-1 (у «1С:Библиотеки» обмен через MARC/XML и полную каталогизацию) | Двойной импорт T1 → создано = 0, обновлено = 0 |
| R-08-2 | Отчёт «Просрочки» на дату одним списком по всем читателям | И-1С-2 (отчётность — статистика фонда; задолженность — по формуляру читателя и в уведомлениях, общего списка должников нет) | Отчёт на T1 строится ≤ 2 сек |
| R-08-3 | Экспорт отчёта в CSV, совпадающий с эталоном | План работ, критерий приёмки 3 + И-1С-2. ☐ Аналитику: подвести инсайт аналога (например, выгрузки аналогов в MXL/XML, а не в CSV) | Расхождение с `golden/overdue.csv` = 0 |
| R-08-4 | Быстрое оформление выдачи с запретом выдачи занятого экземпляра | И-1С-3 (высокий порог входа), UX-инсайты фулстека | Выдача ≤ 1 мин, повторная выдача экземпляра блокируется |
| R-08-5 | Журнал изменений по выдачам: кто и когда выдал, принял, исправил | НФТ кейса «Трассируемость». ☐ Аналитику: подвести инсайт аналога или отзыв пользователей (споры «кто принял книгу») | У каждой выдачи и возврата есть автор и время |
