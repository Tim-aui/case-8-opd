## 1. Проблема пользователя

Библиотекарь небольшой библиотеки не видит всех должников разом. Выдачи ведутся в бумажных формулярах, в таблицах или в полной АБИС, где задолженность смотрят по формуляру конкретного читателя, а не единым списком на дату. Поэтому просрочки замечают поздно, книги долго не возвращаются в фонд, а оборот фонда падает.

## 2. Целевая аудитория

| Сегмент | Задача | Роль в MVP |
|---|---|---|
| **Библиотекарь** | Быстро оформить выдачу и возврат; увидеть список всех просроченных выдач на дату и связаться с должниками | **Основной сегмент MVP** |
| Администратор | Загрузить данные из CSV без дублей; выгрузить отчёт; контролировать журнал изменений | Второй сегмент MVP |
| Читатель | Посмотреть свои выдачи и сроки | Could, после MVP (решение D-5). В MVP актором не является: Use Case и роли 1С нет |

**Почему основной сегмент — библиотекарь:** бизнес-цель кейса («снизить просрочки возврата») достигается действиями библиотекаря. Он выдаёт книги, принимает возвраты и работает с должниками по отчёту «Просрочки». Три из пяти Use Case (UC-08-1, 2, 4) инициирует библиотекарь. Администратор нужен, чтобы в систему попали данные. Читатель в кейсе опционален.

## 3. Vision Statement (шаблон Мура)

> **Для** библиотекарей небольшой библиотеки, **которым нужно** быстро оформлять выдачи и возвраты и в любой момент видеть всех должников,
> **продукт** «Библиотека: выдача и просрочки» — **это** конфигурация 1С:Предприятие для учёта выдач и контроля просрочек,
> **которая** за один шаг строит отчёт «Просрочки» на выбранную дату и выгружает его в CSV.
> **В отличие от** полной АБИС (например, «1С:Библиотека»), где для начала работы нужна каталогизация, а задолженность показывается в формуляре читателя и в уведомлениях, а не общим списком,
> **наш продукт** загружает книги, читателей и выдачи из CSV за минуты, без повторов, и показывает все просрочки одним списком.

| Элемент шаблона | Значение |
|---|---|
| Для кого | Библиотекари небольшой библиотеки |
| Потребность | Быстро оформлять выдачи и возвраты и видеть всех должников на дату |
| Название | «Библиотека: выдача и просрочки» |
| Категория | Конфигурация 1С:Предприятие для учёта выдач и контроля просрочек |
| Ключевая выгода | Отчёт «Просрочки» на дату за один шаг и выгрузка в CSV |
| Главная альтернатива | Полная АБИС («1С:Библиотека» / «1С:Библиотека ПРОФ») |
| Ключевое отличие | Старт из CSV за минуты без каталогизации; все просрочки одним списком |

## 5. Границы системы

### Входит в границы (Must; IN-7 — Should)

Реализуемость каждого пункта на 1С в сроки курса проверил 1С-разработчик (вклад 1С, §2.2; замечания приняты в [review-1c.md](review-1c.md)).

| № | Входит | Реализуемо на 1С | Замечание 1С | Требование |
|---|---|---|---|---|
| IN-1 | Выдача и возврат книги; статусы выдач «Выдана», «Возвращена», «Просрочена», «Возвращена с просрочкой» | Да | Выдача и возврат оформляются документами. Статус не хранится, а вычисляется на дату (A-08-2) | R-08-4 |
| IN-2 | Запрет выдачи занятого экземпляра (одна активная выдача на `book_code`) | Да | Проверка при проведении + управляемая блокировка экземпляра (A-08-5) | R-08-4 |
| IN-3 | Отчёт «Просрочки» на дату (`reader_id, fio, book_code, title, days_overdue`) | Да | СКД с параметром «Дата отчёта». По D-9 две группы — «Просрочена» и «Возвращена с просрочкой» — с колонкой статуса; отбор в запросе, а не в компоновке. Для сверки с golden — вариант «Сводка по читателям» (Д-8) | R-08-2 |
| IN-4 | Импорт `books / readers / loans.csv` с проверками и без дублей | Да | Формат CSV зафиксирован решением D-1; порядок загрузки readers → books → loans; повторный импорт — по D-7 (вклад 1С v1.1, §3.2) | R-08-1 |
| IN-5 | Экспорт отчёта в CSV и сверка с `golden/overdue.csv` | Да, с замечанием | СКД штатно не сохраняет CSV — нужна своя процедура выгрузки (A-08-3) | R-08-3 |
| IN-6 | Роли «Библиотекарь» и «Администратор» | Да | Права задаются ролями, без RLS | — |

## 6. Ограничения и допущения

### Ограничения (заданы заранее, изменить нельзя)

| № | Ограничение | Источник |
|---|---|---|
| О-1 | Платформа 1С:Предприятие 8.3 (учебная версия), собственная конфигурация | Кейс 8, вклад 1С |
| О-2 | Данные поступают только из CSV `books.csv`, `readers.csv`, `loans.csv`; интеграций с АБИС нет | Кейс 8 «Требования к интеграции» |
| О-3 | Отчёт «Просрочки» строится на СКД | ТЗ по ролям, 1С W4–5 |
| О-4 | СКД штатно не сохраняет CSV (только XLSX / MXL / PDF), выгрузку CSV пишем программно | Вклад 1С |
| О-5 | Учебная база в файловом режиме, около 5–10 одновременных пользователей | Лекция 2, вклад 1С |
| О-6 | Только синтетические данные, без реальных ПДн | Кейс 8 «Ограничения» |
| О-7 | Срок — 8 недель; в MVP не больше 5 пользовательских операций (выдать, принять возврат, импортировать, сформировать отчёт, экспортировать) | План работ, кейс 8 «Ограничения» |
