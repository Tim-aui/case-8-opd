## 1. Цитата из карточки кейса

> «Производительность: построение отчёта по ≥100 записям loans — интерактивно. Надёжность: импорт CSV идемпотентен (повторная загрузка не создаёт дублей выдач). Трассируемость: журнал изменений по выдачам (кто/когда выдал/принял/исправил). Доступы: роли — библиотекарь (операции), администратор (настройки, импорт/экспорт), читатель (опционально, только просмотр своих выдач)».

| Атрибут | Есть в кейсе? | Вывод |
|---|---|---|
| Производительность | ✓ есть: «интерактивно» | Задаём число: ≤ 2 сек, APDEX ≥ 0,85 |
| Масштабируемость | ✕ не зафиксирована | Предлагаем сами: рост данных в 10× |
| Надёжность | ✓ есть: идемпотентный импорт | 0 дублей при повторной загрузке |
| Доступность | ✕ не зафиксирована | Предлагаем сами: часы работы библиотеки |
| Сопровождаемость | ◐ косвенно: «трассируемость» (журнал кто/когда) помогает разбирать ошибки выдач | Журнал + изменение отчёта без программирования |

Как в ПР 3–4: «трассируемость» в кейсе — это журнал изменений по выдачам, а не трассируемость R→A из лекции 1 (она в §4).

| NFR-8 | Доступность | Работа в часы библиотеки | ≥ 99% рабочего времени библиотеки; обновление конфигурации — только вне часов работы | Журнал недоступности (дата, начало, окончание, причина; плановая и неплановая) ведёт администратор. В учебном проекте — на период демо-прогонов W5–W8 | Предлагаем сами |
| NFR-9 | Сопровождаемость (трассируемость кейса) | Журнал изменений по выдачам | У 100% документов «Выдача» и «Возврат» видны автор и время создания и каждого исправления; журнал доступен администратору | Проверка истории изменений на 5 исправленных выдачах | ТЗ кейса («журнал изменений по выдачам») |

**Доступ (роли), из кейса:** «Библиотекарь» — операции выдачи и возврата, отчёт, экспорт; «Администратор» — импорт, экспорт, настройки, журнал; «Читатель» — Could, роль в 1С не создаём (D-5). Исправлять выдачи и возвраты могут обе рабочие роли, удалять — только «Администратор» (D-8). Права — по матрице «UC × роль 1С» в `use-cases.md`.

**Конфликт атрибутов:** управляемая блокировка экземпляра при выдаче (надёжность, A-08-5) против скорости импорта больших файлов (производительность, NFR-3). Решение: при импорте правило «одна активная выдача» проверяется одним запросом по всему пакету, а не построчной блокировкой.

## 3. Архитектурные решения и тест «5 да»

Тест из лекции 1:
1. Меняет структуру или границы системы?
2. Влияет на несколько модулей, подсистем или команд (ролей)?
3. Влияет на качество системы?
4. Создаёт долгосрочное ограничение или высокую стоимость изменения?
5. Требует выбора между альтернативами?

| № | Решение | 1 Структура | 2 Несколько ролей / модулей | 3 Качество | 4 Дорого менять | 5 Альтернативы | Итог |
|---|---|---|---|---|---|---|---|
| A-08-1 | Идемпотентный импорт: поиск по ключу (`loan_id`, `book_code`, `reader_id`) → по правилам D-7: пропустить, оформить возврат или отклонить конфликт | Да — нужна проверка дублей перед записью и ключ в регистре выдач | Да — администратор доверяет результату, библиотекарь видит корректные просрочки, фулстек строит такие же фикстуры | Да — надёжность (NFR-5) | Да — переделка импорта затронет уже загруженные данные | Да — альтернатива «запретить повторный импорт» или «очищать базу перед загрузкой» | **5 / 5** |
| A-08-2 | Статус «Просрочена» не хранится, а вычисляется в запросе на дату отчёта | Да — в модели нет хранимого статуса, нет регламентного задания | Да — отчёт 1С, мок-REST и дашборд считают просрочку по одной формуле | Да — производительность (NFR-1) и корректность (NFR-7) | Да — переход на хранимый статус потребует ночного пересчёта и миграции | Да — альтернатива «хранить статус и пересчитывать регламентным заданием» | **5 / 5** |
| A-08-3 | Своя процедура экспорта CSV в формате эталона | Да — появляется отдельный компонент выгрузки | Да — 1С делает выгрузку, фулстек сверяет с golden, аналитик фиксирует формат | Да — надёжность / корректность (NFR-7) | Нет — процедуру легко поменять | Да — альтернатива «сохранять XLSX штатно и конвертировать вручную» | 4 / 5 |
| A-08-4 | 1С — единственная система учёта; веб-прототип работает на мок-REST по OpenAPI и в 1С не пишет | Да — граница: веб не интегрирован с 1С | Да — тимлид (моки), фулстек (UI), 1С | Да — сопровождаемость и независимость сроков | Да — живая интеграция потом потребует HTTP-сервиса 1С | Да — альтернатива «веб с собственной БД» или «HTTP-сервис 1С сразу» | **5 / 5** |
| A-08-5 | Управляемая блокировка экземпляра при проведении «Выдачи» | Нет — структура не меняется | Да — библиотекари, работающие одновременно; импорт (конфликт с NFR-3) | Да — надёжность (одна активная выдача) | Нет | Да — альтернатива «только проверка без блокировки» | 3 / 5 |

**Вывод:** A-08-1, A-08-2, A-08-4 — архитектурные решения (5 «да»). A-08-3 — значимое решение (4 «да»). A-08-5 — проектное, а не архитектурное (3 «да»); фиксируем его для полноты, в ADR не выносим. A-08-1 и A-08-4 станут ADR на W5–6 (ТЗ тимлида: «ADR: платформа 1С; мок-REST вместо интеграций; идемпотентный импорт по loan_id»).

## 4. Трассировка R→A

Номера R-08-x — из реестра в [README §4](README.md#4-реестр-номеров); формулировки — в `requirements.md` аналитика.

| Требование | Смысл | Решение | Что меняется (где в Use Case) | Атрибут / НФТ | Обоснование |
|---|---|---|---|---|---|
| **R-08-1** | Надёжность: импорт CSV идемпотентен, без дублей выдач | **A-08-1** | UC-08-3 «Импортировать данные»: **альтернативный поток А-1** — проверка по `loan_id` (правила D-7): все поля совпадают → строка пропускается («дубль»); в CSV появилась `return_date`, а в 1С выдача активна → оформляется возврат («обновлено»); в 1С возврат уже есть, а в CSV `return_date` пуста → пропуск, 1С не затирается; любое другое расхождение → строка отклоняется («конфликт с данными базы»). Повторная загрузка того же файла: создано = 0, обновлено = 0 | Надёжность, NFR-5 | Кейс прямо требует идемпотентность; исправленный файл можно загрузить повторно без риска; тест «5 да» пройден 5/5 |
| R-08-2 | Отчёт «Просрочки» на дату интерактивно | A-08-2 | UC-08-4: система вычисляет просрочки на дату D в момент построения отчёта | Производительность, NFR-1 | Не нужен ночной пересчёт; отчёт верен на любую дату, в том числе на эталонную |
| R-08-3 | Экспорт CSV совпадает с golden | A-08-3 | UC-08-5 «Экспортировать CSV»: выгружаются ровно строки отчёта; для сверки — сводка по `reader_id` в формате эталона (Д-8) | Надёжность, NFR-7 | СКД штатно не пишет CSV; без единого формата сверку не автоматизировать |
| R-08-4 | Запрет выдачи занятого экземпляра | A-08-5 | UC-08-1 «Выдать книгу»: альтернатива «экземпляр уже выдан → отказ с сообщением» | Надёжность | Два библиотекаря не выдадут один экземпляр одновременно |
| C-08-1 (ограничение) | Без интеграций с АБИС; 8 недель | A-08-4 | Все UC выполняются в 1С; веб-экраны получают данные из мок-REST | Сопровождаемость | Экраны не зависят от готовности 1С; переход на HTTP-сервис 1С — смена одного адреса |

Запись в формате ПР 3–4 для главного решения:

> **R-08-1** Надёжность: импорт CSV идемпотентен, без дублей выдач → **A-08-1** Use Case UC-08-3 «Импортировать данные»: альтернативный поток проверки дублей по `loan_id` (пропустить дубль, принять появившийся возврат, отклонить конфликт — D-7). Критерий: повторный импорт того же файла — создано = 0, обновлено = 0. Тест «5 да»: 5 / 5.
