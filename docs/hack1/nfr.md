# Нефункциональные требования и трассировка — Кейс № 8

**Версия:** 1.1  
**Дата:** 31.10.2026

## НФТ по пяти атрибутам

| ID | Атрибут | Требование и порог | Проверка |
|---|---|---|---|
| NFR-08-1 | Производительность | Отчёт «Просрочки» на T1 строится не более чем за 2 секунды; поиск — не более чем за 1 секунду | Выполнить 10 последовательных запусков и зафиксировать максимальное время |
| NFR-08-2 | Масштабируемость | На T2 объёмом до 10×T1 корректность сохраняется, отчёт строится не более чем за 5 секунд | Сгенерировать T2 с фиксированным seed и повторить импорт и отчёт |
| NFR-08-3 | Надёжность | Повторный импорт создаёт 0 дублей по `loan_id`; одновременно существует не более одной активной выдачи на `book_code` | Дважды импортировать один набор и повторить выдачу занятого экземпляра |
| NFR-08-4 | Доступность | После перезапуска компоненты готовы к демонстрации не более чем за 2 минуты; при ошибке форма сохраняет данные | Перезапустить компоненты, измерить время; имитировать таймаут |
| NFR-08-5 | Сопровождаемость | Все запросы веб-прототипа проходят через один API-клиент; адрес меняется в одном параметре | Заменить адрес сервера без изменения экранов |

## Архитектурные решения A-08-x

| ID | Решение | Обоснование |
|---|---|---|
| A-08-1 | Единый API-клиент; формат перспективного обмена JSON/HTTP | Позволяет заменить мок HTTP-сервисом без переделки экранов |
| A-08-2 | Состояние прототипа хранится на серверной стороне | Позволяет показать выдачу, возврат и ошибки правил |
| A-08-3 | Просрочки и показатели вычисляются единой функцией | Исключает разные определения просрочки |
| A-08-4 | Роль выбирается переключателем без настоящей авторизации | Достаточно для учебного прототипа |
| A-08-5 | CSV используются как согласованный формат входа и экспорта | Обеспечивает воспроизводимость данных и отчёта |
| A-08-6 | Перезапуск мока восстанавливает исходные фикстуры | Делает демонстрацию повторяемой |
| A-08-7 | Импорт идемпотентен по `loan_id`: совпадающая запись пропускается, конфликтующая отклоняется | Реализует решение D-7 и гарантирует 0 дублей при повторном импорте |

## Трассировка требований к решениям

| Требование | Решения | Связь |
|---|---|---|
| R-08-1 | A-08-5, A-08-7 | CSV и идемпотентность обеспечивают проверяемый повторный импорт без дублей |
| R-08-2 | A-08-3, A-08-5 | Единый расчёт и эталонный CSV обеспечивают воспроизводимый отчёт |
| R-08-3 | A-08-5 | Экспорт использует согласованный CSV для обеих ролей |
| R-08-4 | A-08-2, A-08-3 | Серверные правила запрещают повторную активную выдачу по `book_code` и проверяют даты |
| R-08-5 | A-08-2, A-08-4 | Сервер фиксирует событие, а роль ограничивает доступ к журналу |

## Тест «5 да» для A-08-7

| Вопрос | Ответ | Обоснование |
|---|---|---|
| Решение связано с требованием? | Да | Поддерживает R-08-1 |

| Снижает существенный риск? | Да | Исключает дубли выдач и искажение отчёта |

## Зафиксированные правила данных

- Идентификатор экземпляра: `book_code`, не `book_id`.
- Даты: `issue_date <= due_date` и `issue_date <= return_date`, если `return_date` заполнена.
- Условие `due_date <= return_date` не применяется: возврат раньше срока допустим.
- Повторный импорт выполняется по D-7 и не создаёт дублей по `loan_id`.
