## UC-08-1 «Выдать книгу»

**Цель:** библиотекарь оформляет выдачу читателю и получает подтверждение срока возврата.  
**Связь:** R-08-4, R-08-5; A-08-5; экран «Карточка читателя / Выдача».

### Предусловие

Пользователь вошёл под ролью «Библиотекарь». Читатель и экземпляр есть в каталоге. Система может проверить, свободен ли экземпляр.

### Основной поток

1. Библиотекарь открывает карточку читателя.
2. В списке доступных экземпляров выбирает книгу.
3. Указывает дату выдачи и плановую дату возврата.
4. Подтверждает выдачу.
5. Система проверяет существование читателя и экземпляра, корректность дат (`issue_date ≤ due_date`) и отсутствие активной выдачи по `book_code`.
6. Система фиксирует выдачу и записывает автора и время операции в журнал.
7. Система показывает подтверждение с названием книги и сроком возврата.

### Альтернативный поток A1 — экземпляр уже выдан

На шаге 5 система находит незакрытую выдачу с тем же `book_code`, не создаёт новую запись и показывает сообщение:

> «Экземпляр уже выдан читателю {fio} до {due_date}. Выберите другой экземпляр.»

Сообщение — предложение аналитику для согласования с фулстеком; в acceptance-hack1.md этот текст приведён как пример желаемого сообщения.

### Исключение E1 — неверные даты или отсутствующая запись

Если `due_date < issue_date`, система не создаёт выдачу и сообщает: **«Срок возврата раньше даты выдачи. Проверьте даты.»** Если читатель или экземпляр не найден, операция также завершается без записи и система указывает, какую запись не удалось найти.

### Постусловие

При успехе выдача сохранена, экземпляр считается занятым до возврата, а автор и время создания доступны в журнале. При альтернативе или исключении новая выдача не создаётся.

## Остальные Use Case — краткие сценарии

### UC-08-2 «Принять возврат»

- **Актор:** Библиотекарь. **Предусловие:** пользователь вошёл; у экземпляра есть активная выдача.
- **Основной поток:** библиотекарь находит активную выдачу → фиксирует дату возврата → система проверяет `issue_date ≤ return_date` → закрывает выдачу, пишет автора и время → показывает новый статус и результат.
- **Альтернатива:** возврат сделан после `due_date`; операция завершается, статус становится «Возвращена с просрочкой», а запись остаётся в отчёте по D-6.
- **Исключение:** активной выдачи нет либо `return_date < issue_date`; система не меняет запись и объясняет причину.
- **Постусловие:** выдача закрыта; экземпляр доступен; история операции сохранена. **Связь:** R-08-4, R-08-5.

### UC-08-3 «Импортировать данные»

- **Актор:** Администратор. **Предусловие:** пользователь вошёл; подготовлены `readers.csv`, `books.csv`, `loans.csv` с заголовками в формате D-1.
- **Основной поток:** администратор выбирает файлы → система загружает и проверяет читателей → книги → выдачи → проверяет ссылочную целостность, даты и одну активную выдачу на экземпляр → импортирует допустимые строки → показывает протокол: загружено, пропущено, отклонено и причины.
- **Альтернатива A1 — повторный импорт по `loan_id` (D-7):** совпадающая строка пропускается; новая `return_date` закрывает активную выдачу; пустая дата из старого файла не отменяет уже оформленный возврат; конфликт других полей отклоняется. Повтор того же файла: создано = 0, обновлено = 0.
- **Исключение:** файл не читается или обязательная структура отсутствует; импорт соответствующего файла не меняет базу, администратор видит причину.
- **Постусловие:** допустимые данные импортированы без дублей; отклонённые строки объяснены в протоколе. **Связь:** R-08-1, A-08-1.

### UC-08-4 «Сформировать отчёт о просрочках»

- **Акторы:** Библиотекарь, Администратор. **Предусловие:** пользователь вошёл; загружены выдачи, книги и читатели.
- **Основной поток:** актор задаёт дату D и при необходимости фильтр → система выводит `reader_id, fio, book_code, title, days_overdue, status` → пользователь видит список активных просрочек и возвратов с опозданием, сортировку/итоги согласно экрану.
- **Альтернатива:** на дату D просрочек нет; система показывает пустой результат с явным сообщением «Просрочек нет», не маскируя его под ошибку.
- **Исключение:** данные не загружены или дата отчёта некорректна; система объясняет, что исправить.
- **Постусловие:** пользователь получил список просрочек на дату; доля KPI рассчитывается только по активным выдачам (D-6). **Связь:** R-08-2, A-08-2.

### UC-08-5 «Экспортировать CSV»

- **Акторы:** Библиотекарь, Администратор. **Предусловие:** сформирован отчёт о просрочках.
- **Основной поток:** актор выбирает экспорт → система формирует CSV для текущей даты и фильтров с минимумом `reader_id, book_code, days_overdue` и согласованными полями для `golden/overdue.csv` → пользователь сохраняет файл.
- **Альтернатива:** строк данных нет; выгружается CSV с заголовками без строк данных.
- **Исключение:** ошибка создания/сохранения файла; исходный отчёт остаётся доступен, пользователю показывается причина.
- **Постусловие:** файл выгружен; колонки и строки соответствуют согласованному формату. **Связь:** R-08-3, A-08-3.

## Проверка полноты ПР 3–4

1. У каждого первичного актора есть минимум один UC: библиотекарь — UC-08-1/2/4/5; администратор — UC-08-3/4/5.
2. У всех 5 UC описана альтернатива или исключение.
3. Результат каждого UC ценен актору, а не является внутренней операцией системы.
4. BI и уведомления отмечены только как перспективные взаимодействия; активных интеграций в MVP нет.
5. Имена данных соответствуют D-1: `book_code`, `reader_id`, `loan_id`, `fio`, `group`, `issue_date`, `due_date`, `return_date`.
