| Библиотекарь | Первичный | UC-08-1 выдача; UC-08-2 возврат; UC-08-4 отчёт; UC-08-5 экспорт CSV |

Читатель не является актором MVP сайта и не имеет личного кабинета. Он хранится как сущность учёта. Пользовательский интерфейс читателя возможен после MVP.

## UC-08-1 «Выдать книгу»

### Предусловия

1. Библиотекарь выбран как текущая роль.
2. Читатель и экземпляр существуют.
3. Экземпляр с указанным `book_code` не имеет активной выдачи.

### Основной поток

1. Библиотекарь открывает действие «Выдать книгу».
2. Выбирает читателя и экземпляр по `book_code`.
3. Указывает `issue_date` и `due_date`.
4. Система проверяет существование записей, свободный статус экземпляра и `issue_date <= due_date`.
5. Библиотекарь подтверждает операцию.
6. Система создаёт активную выдачу.
7. Система записывает в журнал тип операции, `loan_id`, автора, дату-время и успешный результат.
8. Система показывает «Книга выдана до ДД.ММ.ГГГГ».

### Альтернатива

**A1 — экземпляр уже выдан.** Система не создаёт выдачу, сохраняет выбранного читателя и даты и показывает: «Экземпляр уже выдан другому читателю. Выберите доступный экземпляр».

### Исключения

- Читатель не найден: «Читатель не найден. Выберите существующего читателя».
- Экземпляр не найден: «Экземпляр книги не найден в каталоге».
- `issue_date > due_date`: «Дата планового возврата не может быть раньше даты выдачи».
- Ошибка сохранения: «Не удалось оформить выдачу. Проверьте данные и повторите попытку».

### Постусловия

- При успехе существует одна активная выдача, экземпляр недоступен для повторной выдачи, событие с автором и временем записано в журнал.
- При отказе состояние выдач не изменено; при технической ошибке попытка зафиксирована в журнале с результатом ошибки.

## UC-08-2 «Принять возврат»

### Предусловия

1. Библиотекарь выбран как текущая роль.
2. Существует активная выдача.

### Основной поток

1. Библиотекарь находит активную выдачу.
2. Указывает `return_date`.
3. Система проверяет `issue_date <= return_date`.
4. Библиотекарь подтверждает возврат.
5. Система закрывает выдачу, освобождает экземпляр и пересчитывает просрочку.
6. Система записывает автора и время операции в журнал.

### Альтернатива

**A1 — возврат раньше срока.** Если `return_date < due_date`, возврат принимается как своевременный; это корректная ситуация.

### Исключения

- Выдача уже закрыта: «Книга уже возвращена».
- `return_date < issue_date`: «Дата возврата не может быть раньше даты выдачи».
- Выдача не найдена: «Активная выдача не найдена».

### Постусловия

- При успехе `return_date` сохранена, экземпляр доступен, событие записано в журнал.
- При отказе выдача остаётся активной.

## UC-08-3 «Импортировать данные»

### Предусловия

1. Администратор выбран как текущая роль.
2. Подготовлены CSV `books`, `readers`, `loans`.

### Основной поток

1. Администратор выбирает файлы и запускает импорт.
2. Система проверяет обязательные поля и уникальность ключей.
3. Система проверяет ссылки `reader_id` и `book_code`.
4. Для выдач система проверяет `issue_date <= due_date` и, если возврат заполнен, `issue_date <= return_date`.
5. Система загружает корректные записи.
6. Система показывает количество добавленных, пропущенных и ошибочных строк и протокол причин.

### Альтернатива

**A1 — повторный импорт по D-7.** Для уже существующего `loan_id` идентичная запись пропускается без дубля; конфликтующая запись с тем же `loan_id` отклоняется и включается в протокол.

### Исключения

- Неизвестный `reader_id` или `book_code`: строка отклоняется с указанием поля.
- Нарушено правило дат: строка отклоняется. Проверка `due_date <= return_date` не применяется.
- Для одного `book_code` обнаружены две активные выдачи: конфликтующие строки отклоняются.
- Файл не читается или имеет неверную структуру: импорт не начинается.

### Постусловия

- Корректные записи доступны системе; повторный импорт создал 0 дублей по `loan_id`.
- Ошибочные строки не изменили данные и перечислены в протоколе.

## UC-08-4 «Сформировать отчёт о просрочках»

### Предусловия

1. Выбрана роль библиотекаря или администратора.
2. Данные успешно импортированы.

### Основной поток

1. Сотрудник открывает раздел «Просрочки».
2. Выбирает дату отчёта D и при необходимости фильтры.
3. Система определяет просроченные выдачи и календарные дни просрочки.
4. Система показывает строки отчёта и итоговые показатели.

### Альтернатива

**A1 — просрочек нет.** Система показывает: «Просрочек на ДД.ММ.ГГГГ нет» и нулевые итоги.

### Исключения

- Дата не задана или имеет неверный формат: «Укажите корректную дату отчёта».
- Ошибка расчёта: «Не удалось сформировать отчёт. Повторите попытку».

### Постусловия

- Сформированный отчёт доступен для просмотра и UC-08-5 «Экспортировать CSV».
- Исходные данные не изменены.

## UC-08-5 «Экспортировать CSV»

### Предусловия

1. Выбрана роль библиотекаря или администратора.
2. Отчёт о просрочках сформирован на дату D.

### Основной поток

1. Сотрудник нажимает «Экспорт CSV».
2. Система формирует CSV из текущего отчёта.
3. Система передаёт файл сотруднику.
4. Сотрудник сохраняет файл для проверки или дальнейшей работы.

### Альтернатива

**A1 — пустой отчёт.** Система формирует CSV только с заголовками и датой отчёта либо сообщает об отсутствии строк согласно согласованному формату.

### Исключения

- Отчёт ещё не сформирован: «Сначала сформируйте отчёт о просрочках».
- Ошибка создания файла: «Не удалось экспортировать CSV. Повторите попытку».

### Постусловия

- Библиотекарь или администратор получил CSV, соответствующий отображённому отчёту.
- Данные системы не изменены.

## Перспективные взаимодействия

- Сервис уведомлений после MVP может получать сведения о просрочках по JSON/HTTP.
